# Плагин VPNRouter для Omarchy Quattro

Нативный плагин QML и Quickshell для Omarchy Quattro, обеспечивающий интеграцию VPNRouter в системную панель рабочего окружения.

- **Идентификатор манифеста:** `io.github.pavellizunov.vpnrouter`
- **Лицензия:** GNU General Public License v3.0 (GPL-3.0)
- **Основной репозиторий:** [PavelLizunov/VPNRouter](https://github.com/PavelLizunov/VPNRouter)
- **Спецификация протокола:** Протокол v1 (`plans/omarchy-protocol-v1.md` в репозитории VPNRouter)

---

## Текущий статус разработки и область ответственности

> **СТАТУС ЧЕРНОВИКА:** Этот репозиторий и плагин являются ранним рабочим черновиком (draft) и **НЕ предназначены для продуктивного использования**.

Этот репозиторий содержит интерфейс плагина для Omarchy Quattro, сценарии сборки/развертывания и скрипт-обертку запуска.

- **Контракт backend:** Плагин согласован с `VPNRouter.Headless` в коммите `29dcca1a29a670f0a45cf44a72fa639231427040`, upstream [PR #616](https://github.com/PavelLizunov/VPNRouter/pull/616). Необязательные поля четвёртого этапа описаны ниже. Интерфейс проверяется в работающей тестовой VM с Omarchy 4.0.4 / Quickshell 0.3.1 и offscreen на компонентах более нового установленного хоста. VPN-соединение и маршрутизация трафика не проверены.
- **Доступность:** Подключение разрешено только при `capabilities.connect=true`. Карточка переводит необязательный `unavailableReasonCode`; со старым backend показывает `unavailableReason` без изменения текста. При отсутствии backend появляется подсказка об установке `vpnrouter-headless`, автоматические повторы прекращаются. При других завершениях процесса задержка растёт от 2 до 30 секунд и сбрасывается только после успешного ответа snapshot.
- **Проверка серверов:** Результат проверки, задержка или причина ошибки отображаются на вкладках серверов и бесплатного пула. Kill switch и DNS lockdown на Linux недоступны. Сохранённое предпочтение DNS lockdown не показывается активным и не отправляется повторно, если функция недоступна.

## Открытие раздела сочетанием клавиш

Значок панели и `omarchy-shell shell toggle io.github.pavellizunov.vpnrouter '{}'`
открывают плагин. Для конкретного раздела используйте отдельный IPC target:

```bash
omarchy-shell io.github.pavellizunov.vpnrouter.ui open '{"page":"servers"}'
omarchy-shell io.github.pavellizunov.vpnrouter.ui open '{"page":"servers","form":"import"}'
omarchy-shell io.github.pavellizunov.vpnrouter.ui open '{"page":"subscriptions","form":"add"}'
```

Разделы: `home`, `servers`, `subscriptions`, `apps`, `rules`, `settings`,
`diagnostics`, `free`, `profiles`, `custom`. Формы открывают локальный черновик
без отправки данных. Неизвестные разделы/формы и payload длиннее 1024 символов
возвращают `invalid`. Монитор выбирает хост по текущему фокусу. Omarchy 4.0.4
отбрасывает payload при обычном summon для bar-widget; для разделов нужен этот target.
Необязательное поле `"locale":"en"`, `"ru"` или `"auto"` меняет язык панели
в текущем сеансе shell без сохранения конфигурации оболочки.
Если в хосте нет `Commons.I18n`, автоматический язык определяется по `LANG`.

## Приложения, первый запуск и источники серверов

Главная сохраняет название Virtual Penguin Network, оригинального маскота,
кольцо статуса, кнопку подключения и сегменты маршрутизации. Цвета, типографика,
отступы и геометрия контролов берутся из установленных `Color`, `Style`, `Border`
и `Ui` Omarchy. Подключение использует accent темы, ошибки и недоступность — urgent,
Иконка бара использует заполненные Material-щиты со штатным размером и
выравниванием: отключённое состояние — foreground, запуск — muted. Нейтральные
отметки панели — muted. Яркость фона popup выбирает исходный чёрный или белый
PNG маскота; байты изображений не меняются. Fitting и жизненный цикл принадлежат
панели Omarchy.

Если списки серверов и подписок пусты, «Добавить подписку» в карточке подключения
или разделе серверов открывает форму подписки. Открытие формы ничего не загружает.
«Изменить» открывает серверы. Строки на главной ведут в расширенные разделы;
закреплённая стрелка возврата возвращает фокус на исходную строку. Общая рамка
и внутренняя прокрутка сохраняют геометрию при переходах и открытии форм.
Tab обходит элементы, Escape закрывает панель. Enter отправляет однострочные
формы; многострочные редакторы сервера и конфигурации используют Ctrl+Enter.

Раздел приложений использует необязательные данные `apps.list.runningApps`:
название, значок freedesktop и точное имя процесса с учётом регистра. По умолчанию
показаны приложения с desktop-записью или открытым окном Hyprland (сопоставление
имени процесса с классом окна либо PID, если он передан службой). Остальные
процессы свёрнуты в отдельный раздел со счётчиком. Поиск по названию и имени
процесса охватывает оба раздела и раскрывает совпадения. Подсказок не больше 200;
ручной ввод имени процесса остаётся доступен. Со старым backend остаются ручной
ввод и выбранный список; вместо неразобранного списка процессов показано пояснение.

Серверы сгруппированы по ручному источнику или названию подписки. Удаление
доступно только при `removable=true`; без новых полей показана группа с неизвестным
источником без кнопки удаления. Backend повторно проверяет возможность удаления.
Уровни диагностики и сообщения первого запуска переведены, остальные сообщения
backend показаны дословно. Блокировка трафика без VPN недоступна на Linux и
снабжена пояснением; доступность DNS-lockdown определяется capability backend.
Неподдерживаемое поле DNS-lockdown не отправляется при сохранении.

Маршрутизация задаётся явным выбором: **Только выбранные приложения / Весь
трафик**. В раздельном режиме доступны варианты **Через VPN только выбранные /
Все, кроме выбранных**. На главной доступны «Приложения / Весь трафик»; политика
включения или исключения задаётся в разделе приложений.

На главной запуск службы показан отдельно от подключения VPN. Если статус
не удалось получить, причина ошибки остаётся видимой.

Ссылка подписки по умолчанию скрыта. Формы импорта сохраняют ввод при ошибке и
очищают его после успеха или отмены; пустой и некорректный ввод получает пояснение.
В открытой форме одна строка действий; «Отмена» возвращает фокус к добавлению или импорту.
Кнопка **Отменить изменения** в настройках восстанавливает последние значения,
полученные от службы. CIDR передаются службе без потерь для проверки, а не
удаляются молча. Многострочные редакторы прокручиваются внутри; Enter добавляет
строку, Ctrl+Enter отправляет форму, Tab переводит фокус дальше. У кнопок-иконок
есть штатные подсказки на выбранном языке; текст сообщения отмечается цветом
акцента темы, когда получает фокус.

Экспорт правил показывает сохранённые правила отдельным текстом для копирования,
сохраняет несохранённые правки и не создаёт файл. Экспорт диагностики показывает
полный путь, полученный от службы: его можно выделить и скопировать. Перед
повторной попыткой старый путь скрывается.

В диагностике сохраняются сообщения и статусы всех проверок. Повторяющийся
заголовок `HealthCheck` скрыт у строк с сообщением; содержательные имена остаются.

## Безопасность и архитектурные инварианты

Скрипты установки и запуска строго изолируют привилегии:

1. **Запрет сбора паролей и работа без привилегий:**
   Плагин и скрипт установки никогда не запрашивают пароль суперпользователя, не используют `sudo -S`, не редактируют `/etc/sudoers.d/` и не настраивают правила `NOPASSWD`.
   **Повышение привилегий движка и статус маршрутной фильтрации файрволом:**
   Непривилегированный характер скрипта установки и обертки запуска **не является доказательством того, что движок не может повышать привилегии**: существующие реализации `VPNRouter.Core` в Linux могут использовать `pkexec` для выполнения привилегированных операций. Утверждение архитектурного дизайна выделенного привилегированного брокера/хелпера всё ещё **ОЖИДАЕТСЯ (PENDING)**. Привилегированная фильтрация сетевых маршрутов через файрвол (`killSwitch` и `dnsLockdown`) **НЕ** завершена и ожидает утверждения и реализации этого сервиса (отслеживается в upstream [plans/OPEN-DEFECTS.md](https://github.com/PavelLizunov/VPNRouter/blob/main/plans/OPEN-DEFECTS.md)). Фоновый процесс сообщает `capabilities.killSwitch: false` и `capabilities.dnsLockdown: false`. Маршрутная фильтрация через Polkit не реализована; скрипт установки не настраивает и не заявляет о наличии работающих правил kill-switch.

2. **Детерминированный запуск (защита от PATH injection, отсутствие backdoor-переменных окружения, запрет symlink):**
   Обертка запуска `bin/vpnrouter-headless` обращается только к фиксированным путям:
   - Локальная полезная нагрузка бэкенда: `<директория_плагина>/bin/backend/VPNRouter.Headless`
   - Системный бинарный файл: `/usr/lib/vpnrouter-headless/VPNRouter.Headless`
   Скрипт никогда не ищет бинарный файл в переменной `$PATH`, отклоняет исполнение по символическим ссылкам и не содержит скрытых переопределений через переменные окружения. При отсутствии бэкенда выполнение завершается с кодом ошибки 127 без попыток автоматической загрузки из сети.

3. **Строгая фильтрация аргументов протокола v1 и локальная справка:**
   Обертка принимает исключительно аргументы, предусмотренные контрактом протокола (`--stdio`, `--data-dir <АБСОЛЮТНЫЙ_ПУТЬ>`). Справка (`--help`, `-h`) генерируется локально без запуска исполняемого файла бэкенда. Любые несанкционированные флаги (включая `--version`), а также передача произвольного ввода отклоняются с кодом ошибки 2.

4. **Отказ от обновления при активном бэкенде (отсутствие претензий на бесконфликтное обновление на лету):**
   Скрипт установки проверяет наличие запущенного процесса бэкенда. При обнаружении активного процесса скрипт прерывает работу с ошибкой и **никогда** не отправляет сигналы `SIGTERM` или `SIGKILL` и не завершает процессы принудительно. Пользователь или служба должны остановить бэкенд явно перед установкой обновления. Скрипт не заявляет о возможности бесконфликтной замены бинарника активного процесса на лету.

5. **Единая директория полезной нагрузки и замена с резервной копией (полный запрет symlink, безопасная подготовка):**
   Валидатор Omarchy категорически запрещает любые символические ссылки внутри плагина. Все материалы бэкенда размещаются в единой относительной директории `bin/backend/`. Наличие symlink, файлов с ведущим дефисом или файлов с точкой на конце в исходных материалах строго запрещено. Промежуточная подготовка выполняется во временной директории рядом в `bin/`, после чего существующая `bin/backend/` временно сохраняется в резервную копию и заменяется новой директорией. (Замена директории не является атомарной операцией обновления активного процесса; при отказе валидации или прерывании выполняется автоматический откат).

6. **Отказ при неизвестном состоянии блокировки сессии (Fail-Closed):**
   На рабочей системе с `omarchy-shell` скрипт запрашивает статус блокировки. Если статус не может быть проверен, запрос завершился ошибкой, тайм-аутом или сессия заблокирована, выполнение немедленно прерывается с ошибкой. Проверка статуса блокировки строго требует Python 3 (без ненадежного `jq` fallback).

7. **Валидация манифеста и плагина после финальной установки с откатом:**
   Проверка структуры манифеста, отсутствия символических ссылок и валидация плагина хостом (`omarchy plugin validate`) выполняются строго ПОСЛЕ окончательного размещения файлов в `bin/backend/`. При отказе валидатора хоста установка прерывается с возвратом к исходному состоянию.

8. **Безопасное рукопожатие по протоколу (изоляция от пользовательской конфигурации):**
   Совместимость с Protocol v1 проверяется через `--stdio` с передачей свежей приватной временной директории в `--data-dir`, чтобы setup не запускал бэкенд на рабочей конфигурации пользователя. Используется чтение через селектор с монотонным тайм-аутом, проверка лимита 256 КиБ до помещения в буфер, отбрасывание stderr без утечки секретов и строгая проверка версии протокола (целое число 1), соответствия идентификатора запроса, объектов result/error и отклонение неизвестных полей.

9. **Гарантированное сохранение пользовательских данных:**
   Профили VPN, ключи и правила маршрутизации хранятся в `~/.config/vpnrouter`. Операции установки, обновления и удаления плагина никогда не изменяют и не удаляют пользовательские файлы конфигурации.

10. **Отсутствие неявной активации и перезапусков:**
    Запуск скрипта установки не включает плагин в оболочке, не перезапускает сервисы и не поднимает VPN-соединение автоматически. Активация выполняется пользователем явно.

## Зависимости

### Системные зависимости
- Ядро Linux с поддержкой модуля TUN
- Графическая оболочка Omarchy Quattro с Quickshell
- Пакет `iproute2` (утилита `ip`)
- Python 3 (необходим для работы скриптов упаковки и проверки; без ненадежного `jq` fallback)
- *Статус файрвола:* функции `killSwitch` и `dnsLockdown` ожидают реализации системного привилегированного брокера (`capabilities.killSwitch: false`, `capabilities.dnsLockdown: false`).

### Требования к backend

Пакет Arch `vpnrouter-headless` устанавливает `/usr/lib/vpnrouter-headless/VPNRouter.Headless` и зависимости .NET. Runtime находится в `/usr/lib/vpnrouter-headless/runtime/sing-box`; установочный hook пакета назначает file capabilities. Перед разрешением подключения backend проверяет владельца, права и capabilities runtime. Локальная publish-сборка внутри плагина сама по себе не устанавливает этот системный runtime. Kill switch и DNS lockdown на Linux недоступны.

## Установка и настройка

После установки пакета `vpnrouter-headless` скопируйте файлы проверенного коммита в обычный каталог плагина:

```bash
plugin_dir="$HOME/.config/omarchy/plugins/io.github.pavellizunov.vpnrouter"
mkdir -p "$plugin_dir"
git archive HEAD | tar -x -C "$plugin_dir"
omarchy plugin validate "$plugin_dir"
omarchy-shell shell rescanPlugins
omarchy plugin enable io.github.pavellizunov.vpnrouter --section right
omarchy restart shell
omarchy plugin list --json
```

Команды выполняются из этого репозитория на проверенном коммите. Если локального payload нет, wrapper использует системный backend; `setup --backend-dir` для этого пути не требуется. Логи shell: `journalctl --user -t omarchy-shell -b -f`. Проверки разработки не устанавливают и не включают плагин.

Для локальной publish-сборки backend доступен следующий необязательный путь.

### 1. Сборка бэкенда из исходного кода
В локальной копии репозитория `VPNRouter`:
```bash
dotnet publish VPNRouter.Headless/VPNRouter.Headless.csproj \
  -c Release \
  -r linux-x64 \
  --self-contained \
  -o /tmp/vpnrouter-headless-build
```

### 2. Запуск установки плагина
Укажите путь к директории с собранным бэкендом:
```bash
./setup --backend-dir /tmp/vpnrouter-headless-build
```
Скрипт подготавливает материалы в промежуточной временной директории, выполняет безопасное рукопожатие по протоколу в приватной временной директории данных, создает резервную копию предыдущей `bin/backend/`, устанавливает новую полезную нагрузку и выполняет валидацию манифеста хостом после установки с автоматическим откатом при ошибке. Каталог publish должен содержать `profiles/default.json` и `profiles/default-linux.json`; setup сохраняет их пути и содержимое. Отсутствующие каталоги профилей, символические ссылки, специальные файлы и файлы профилей размером больше 1 МиБ отклоняются до запуска бэкенда для handshake. Другие подкаталоги рекурсивно не копируются.

### 3. Проверка статуса
Проверьте статус установки и совместимость протокола без изменения файлов:
```bash
./setup --status
```

### 4. Включение скопированного плагина

После копирования в каталог пользовательских плагинов и повторного сканирования, как описано выше:
```bash
omarchy plugin enable io.github.pavellizunov.vpnrouter
```

## Обновление и удаление

### Обновление бэкенда
Перед обновлением убедитесь, что активный бэкенд остановлен. Повторно запустите скрипт установки с указанием новой директории сборки:
```bash
./setup --backend-dir /path/to/updated-build
```
Скрипт проверяет отсутствие запущенных процессов, подготавливает файлы во временной папке рядом, валидирует протокол v1, архивирует старую `bin/backend/`, перемещает новую версию на место и валидирует структуру плагина после установки (выполняя откат при отказе). Пользовательские настройки в `~/.config/vpnrouter` остаются нетронутыми.

### Удаление бэкенда
Для удаления установленных файлов бэкенда:
```bash
./setup --remove
```
Команда удаляет `bin/backend/`. Все пользовательские профили VPN, ключи и конфигурация в `~/.config/vpnrouter` сохраняются в полном объеме.

## Проверка протокола

Инструмент проверки анализирует совместимость протокола безопасно:
- **Версия транспортного протокола:** Проверяет соответствие формату Protocol v1 (`v:1` в виде JSON-строк через `--stdio`) с ограничением по объему вывода и таймауту относительно свежей временной директории данных `--data-dir`.
- **Зона ответственности координатора:** Скрипт установки не выдумывает произвольных проверок флага `--version` и не применяет резервные варианты.

## Настройки DNS

Элементы управления и подсказки DNS в текущем черновике описывают редактируемые параметры конфигурации и пользовательские предпочтения, а **НЕ текущее активное состояние DNS** и сетевой маршрутизации в операционной системе.

Режим DNS читается из выбранного профиля и показан только для чтения. Текущий
Core отклоняет запись режима через `settings.set`, поэтому плагин не отправляет
это поле. Strict DNS и полный туннель по-прежнему влияют на пояснение в интерфейсе.
Недоступное поле DNS-lockdown не отправляется повторно и не отключается молча.

## Тестирование

Все тесты выполняются в изолированном тестовом окружении для **черновика** и не свидетельствуют о подтвержденной готовности к продуктивной эксплуатации.

### Тесты упаковки и изоляции
Запуск набора тестов упаковки и изоляции (использует только стандартную библиотеку Python, не требует внешних пакетов, сетевого доступа или запущенной оболочки):
```bash
python3 tests/test-packaging.py
```
Тесты проверяют обработку отсутствующего бэкенда, установку из директории без бэкдоров в переменных окружения, отсутствие символических ссылок после установки, валидацию манифеста хостом после окончательной установки с откатом при ошибке, безопасное рукопожатие в изолированной временной директории данных без обращения к пользовательским настройкам, отказ от обновления при активном бэкенде, сохранение конфигурации в `~/.config/vpnrouter` и строгую фильтрацию аргументов обертки.

### Логика UI и нативная offscreen-проверка

Каждый `tests/test-ui-*.js` запускается через Node. Новый `tests/test-ui-r4.js`
проверяет production Model и функции QML: метаданные приложений, старый backend,
источники серверов, причины недоступности, переход первого запуска и валидацию.
`tests/qml-r6-consumer.qml` загружает настоящие Panel, Service и locale-файлы с
`processDisabled=true` и инертными ответами протокола. Внешний `qml-render` с
адаптером layer-shell → Item позволяет проверить настоящие события Qt мыши и
клавиатуры и снять настоящий consumer с установленными темами Omarchy. Это не проверка
compositor, VPN или сетевых операций.

`node tests/test-ui-theme.js` запрещает hex-цвета и фиксированные семейства шрифтов
в production QML/JS и проверяет все экспорты `ui/qmldir`. При наличии внешнего
[qml-preview-mcp](https://github.com/PavelLizunov/qml-preview-mcp) матрица проверок запускается без Quickshell:

```bash
bwrap --unshare-net --bind / / --dev /dev --proc /proc -- \
  python3 -B tests/render-theme-matrix.py --evidence-dir /tmp/vpnrouter-theme-review
```

Runner генерирует файлы тем установленным шаблонизатором Omarchy в приватных
каталогах. Renderer читает их штатными startup FileView `Color` в изолированном
HOME. Проверяются Catppuccin Latte, Tokyo Night и Hackerman, EN/RU, шесть состояний
главной, серверы, настройки и список разделов. Эталон Bluetooth использует инертные
устройства. На Item заменено только layer-shell окно; UI host и плагина — настоящий QML.

### Изолированное тестирование компонентов QML (offscreen shim)
Скрипт автоматического запуска тестов QML проверяет синтаксис, загрузку компонентов и модели интерфейса offscreen:
```bash
tests/qml-test-runner.sh
```
Эти тесты выполняются в изолированном стенде Qt/QuickShell с использованием экранного адаптера-заглушки (shim) `KeyboardPanel`. Они **НЕ являются реальным приемочным тестированием на хосте** (host acceptance) в живой графической сессии Omarchy Quattro и не подтверждают интеграцию с живой оболочкой через IPC или работу в реальном интерфейсе.

### Проверка настоящего publish-бэкенда (Linux, по явному запуску)

Для доверенной локальной publish-директории с доступной требуемой средой .NET:
```bash
PYTHONDONTWRITEBYTECODE=1 python3 tests/check-published-backend.py /path/to/trusted/publish
```
Тест запускает переданный бэкенд во временной копии плагина с заглушками команд
Omarchy. Проверяются setup, штатная обёртка, `profiles.list`, отсутствие записи
настроек и завершение по EOF. Первый сценарий использует неизменённые каталоги;
второй добавляет уникальное имя только во временный Linux-каталог для проверки
выбора платформы. Исходная publish-директория не изменяется. Это не проверка
live-shell, подлинности бинарников или VPN-соединения.
